1. PHASE 0 -- SCAFFOLDING (prerequisite, also complete)
--------------------------------------------------------------------------------

src/config.py                          126 lines
    Frozen Config dataclass. Every tunable in the pipeline is read from here
    exactly once. Exports CONFIG as a shared instance.
    Notable: chunk_size_tokens=200, chunk_hard_cap_tokens=240,
    chunk_overlap_tokens=25, min_block_chars=40, min_similarity=0.35.
    Paths resolve relative to PROJECT_ROOT, not the CWD.

src/models.py                          142 lines
    Data contracts shared by every stage. Dataclasses only, no logic.
      Source      - one URL from data/sources.md
      TextBlock   - section + text + kind ("prose"|"table"|"list")
      Document    - all blocks for one page, with ingested_at
      Chunk       - embeddable unit + all metadata needed to cite it
                   (has .embedding_text() which adds the scheme/section
                   prefix used in Phase 2)
      Hit         - retrieved chunk + similarity score
      Answer      - final response + hits, for the UI and the debug panel
    Also: make_chunk_id() = sha1(source_url|section|chunk_index). Deterministic
    ids are what let a re-ingest upsert in place instead of duplicating rows.

src/cli.py                              87 lines
    argparse entry point. Subcommands: ingest [--force] [--refresh],
    ask "<question>", inspect.
    Heavy imports (chromadb, sentence-transformers, anthropic) are deferred
    into the handlers, so --help and ingest work before those are installed.

3. PHASE 1.2 -- FETCHER (cache-first)
--------------------------------------------------------------------------------

src/ingest/fetcher.py                   93 lines
    fetch() returns raw HTML, cached to cache/raw_html/<scheme_key>.html.
      - Reuses the cache unless refresh=True. This is architecture decision
        D10 and is what stops a DOM change or flaky network from breaking a
        live demo.
      - Browser-like User-Agent (a default python-requests UA gets blocked).
      - Retries on 429/5xx with 2s/4s/8s backoff, 3 attempts.
      - Raises RuntimeError after exhausting retries.
    Politeness sleep lives in the caller (pipeline), not here.

    Generated (gitignored):
    cache/raw_html/*.html               5 files, 2.6M total

4. PHASE 1.3 -- EXTRACTOR (DOM -> text blocks)
--------------------------------------------------------------------------------

src/ingest/extractor.py                351 lines
    The highest-risk module. extract() walks the DOM in document order and
    emits TextBlocks carrying their heading context.

    Why section/kind are preserved instead of flattening to one string:
    they are what make heading-aware chunking (Phase 2) and precise
    citations (Phase 4) possible.

    Key functions:
      extract()            - main entry; optional stats dict reports drops
      _walk()              - recursive document-order walk
      _flatten_table()     - one line per <tr>, cells joined by " | "
      _flatten_list()      - one "- item" per line
      clean_text()         - collapse whitespace, strip zero-width,
                            redact 12+ digit runs
      clean_prose()        - same, plus collapse source line wrapping
                            (prose only; tables/lists keep their newlines)
      coverage_report()    - which answerable fields are present
      missing_fields()     - the inverse

    Filters, and why each exists (do not simplify these away):
      STRIP_TAGS                - script/style/noscript/nav/header/footer/
                                  aside/form/svg
      NOISE_MARKERS             - cookie/consent/popup/newsletter, PLUS
                                  header/footer/navbar/dropdown/carousel.
                                  Needed because Groww wraps its whole shell
                                  in <div class="header2025_headerContainer__">
                                  -- a CUSTOM ELEMENT, so a literal <header>
                                  selector cannot catch it.
      BLOCKED_SECTION_PREFIXES  - Holdings, Return calculator, Compare
                                  similar funds. Returns/holdings are
                                  forbidden by the PRD; holdings alone were
                                  24,562 of 39,880 chars on one page.
      BLOCKED_CONTENT_MARKERS   - marketing ("demat account", "etf screener",
                                  ...) and returns tables ("fund returns",
                                  "category average").
      BLOCKED_CONTENT_PREFIXES  - "address". The AMC postal address is
                                  byte-identical on all 5 pages and would eat
                                  4 of 4 TOP_K slots.
      min_block_chars = 40      - tested at 30, REVERTED. At 30 it admitted a
                                  carousel of OTHER HDFC schemes, which would
                                  cite the wrong scheme confidently. Short
                                  values do not need it relaxed, because
                                  structured.py supplies them exactly.

5. PHASE 1.3b -- STRUCTURED FACTS  (ADDED, NOT IN THE ORIGINAL PLAN)
--------------------------------------------------------------------------------

src/ingest/structured.py               179 lines
    THE BIGGEST FINDING OF PHASE 1. Groww is a Next.js app: every fact the
    FAQ needs is NOT in the rendered HTML. It lives in a JSON payload at
    <script id="__NEXT_DATA__"> -> props.pageProps.mfServerSideData.

    Proof it matters: a prose-only scrape found ZERO occurrences of
    "expense ratio" across all 5 pages. The payload has all of them.

      load_server_data()  - pull mfServerSideData, {} if absent
      extract_facts()     - emit labelled "label | value" table blocks
      facts_summary()     - flat dict for the CLI report

    Output looks like:
      Fees, exit load and investment limits
        Expense ratio | 1.03%
        Exit load | Exit load of 1% if redeemed within 1 year
        Lock-in period | 3 years        <- ELSS only; row omitted when null
        Minimum SIP amount | INR 100
      Benchmark, risk and scheme profile
        Benchmark | NIFTY 100 TRI
        Riskometer | Moderately High Riskometer

    Design: ALLOWLIST, not blocklist. FACT_SECTIONS names every field we
    ingest. EXCLUDED_FIELDS names what must never be ingested --
    return_stats, simple_return, sip_return, nav, groww_rating, crisil_rating,
    peerComparison, aum, historic_*. All are present and reachable in the
    payload; excluding them at the source is how the PRD's "no performance
    claims" rule is enforced STRUCTURALLY rather than by prompt.

    Missing payload is NOT an error -- falls back to prose only.

6. PHASE 1.4 -- PIPELINE / CLI WIRING
--------------------------------------------------------------------------------

src/ingest/pipeline.py                 193 lines
    run_ingest(force, refresh) orchestrates the offline run.
      - load sources -> fetch -> extract_facts -> extract -> write
      - Fact blocks are prepended so authoritative numbers lead the document
        and the chunker does not have to compete with prose for room.
      - ONE failing source is recorded in failures[] and does not abort the
        run. One broken page must not cost us the other four.
      - All schemes share ONE ingested_at timestamp per run.
    _print_coverage() distinguishes two cases on purpose:
      - missing from ALL schemes -> real ingestion failure, WARNING
      - missing from SOME schemes -> often correct (lock-in is ELSS-only),
        printed as a Note, not a warning. Avoids crying wolf.
    inspect_index() prints the manifest (collection stats come in Phase 2).

    Generated (NOT yet gitignored, NOT yet committed):
    data/documents/*.json               5 files, 24K -- cleaned text per scheme
    data/index_manifest.json            8K -- ingested_at, per-source blocks/
                                        chars/sections/coverage/facts, failures

8. TWO BUGS HIT DURING IMPLEMENTATION (both fixed, both now regression-tested)
--------------------------------------------------------------------------------

a) AttributeValueList crash
   tag.get("class") returns a LIST for multi-valued attributes, so the naive
   " ".join() in _is_noise() raised "expected str instance". Fixed with
   _attr_text() normaliser.

b) Decomposed-tag crash
   soup.find_all() returns a list; decompose() on an outer element also
   decomposes its descendants, which are STILL in that list. Iterating them
   gave "'NoneType' object has no attribute 'get'". Fixed with explicit
   .decomposed guards in both the filter loop and the DOM walk.

   Both are classic bs4 traps. If selectors are ever rewritten here, expect
   them again.
