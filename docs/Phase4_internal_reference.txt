3. test_chain.py WAS ADDED BEYOND THE SPEC, DELIBERATELY

  The spec asks for three test files. It is easy to read that as sufficient and
  stop there -- but the spec's other test file, test_acceptance.py, only runs
  with a key. Since no key exists, following the plan literally would have left
  the entire online path unverified: no coverage of the fabricated-URL repair,
  the uncited-answer path, or the API-exception fallback.

  test_chain.py stubs the Claude client and pins exactly those paths:

    - a good answer carries the citation
    - a fabricated URL is repaired to the top hit's canonical URL
    - an uncited answer becomes NO_MATCH
    - an API exception returns NO_MATCH and does NOT raise
    - a failing call makes EXACTLY ONE api call (proves no retry loop)
    - advice / PII / out-of-corpus queries make ZERO api calls (proves ordering)
    - last_updated equals manifest.ingested_at, not anything the model said

  Net effect: when a key is added, the acceptance tests exercise a pipeline
  already known to work, rather than being the first thing to touch it.


4. FIVE REAL BUGS FOUND WHILE BUILDING THIS PHASE

  None of these were hypothetical. Each was caught by a test that failed, and
  two of them would have been invisible in a live demo.

  4.1  TRUNCATION WAS DELETING THE CITATION  (G1 VIOLATION, the bad one)

    The first implementation re-attached the URL and THEN applied the sentence
    cap. "Source: https://..." therefore counted as a 4th sentence and was
    truncated away -- on every answer that hit exactly 3 sentences, which is
    the normal case given rule 1 of the system prompt.

    G1 is "100% of answers carry a source link". This broke it precisely when
    an answer was well-formed. A 3-sentence answer came back with no citation.

    Fixed by ordering: strip URLs -> cap the PROSE -> attach the citation. The
    link is now structurally incapable of being truncated.

        $ pytest tests/test_citations.py -k survives -q
        1 passed

    test_citation_always_survives_truncation pins it.

  4.2  UNCITED ANSWERS WERE BEING BACKFILLED INSTEAD OF REJECTED

    architecture 5.8 step 3 is explicit: if the answer is not a refusal and no
    valid URL remains, return NO_MATCH. The first implementation instead bolted
    the top hit's canonical URL onto the prose.

    That is wrong twice over. It ships a link the model did not choose, and it
    makes G1 unfalsifiable -- if the function manufactures its own citations,
    "100% of answers carry a link" is true by construction and measures nothing.

    Now the two cases are distinct:
      - URL present but fabricated -> substituted (spec step 2)
      - URL absent entirely          -> NO_MATCH      (spec step 3)

  4.3  Answer.refused LIED AFTER A NO_MATCH DOWNGRADE

    When validate() converted an uncited answer to NO_MATCH, chain.answer()
    still returned refused=False. The UI would have rendered a refusal string
    as a successful answer: no citation, no refusal marker, no explanation.

    Caught by test_uncited_answer_becomes_no_match asserting result.refused.
    chain.py now propagates the downgrade.

  4.4  THE REFUSAL PATH RETURNED A 2-TUPLE, NOT A 3-TUPLE

    validate() returns (text, citation_url, truncated). The refusal branch
    returned the result of _enforce_sentences(), which is a 2-tuple. Any caller
    unpacking three values got a ValueError -- on the exact path that handles
    PII and advice refusals, i.e. the paths most likely to run in a demo.

  4.5  A CONFIG ATTRIBUTE GUESS LEAKED A TRACEBACK TO THE TERMINAL

    _ingested_at() used cfg.data_dir; the real field is cfg.manifest_path. This
    crashed every chain.answer() call -- including the guard refusals, which
    happen before any generation -- with a raw AttributeError traceback.

    It is worth recording because it directly violates the phase's central
    requirement: "NEVER lets an exception reach the UI". The first thing to do
    with that traceback is a defensive test asserting chain.answer() does not
    raise for any input class; there is one now, for the API-error path.


5. src/rag/guards.py                     118 lines  (NEW)

  The spec calls a guard false positive "the most damaging bug in this phase",
  and the asymmetry drives the design: a false negative is a privacy incident,
  a false positive is an annoying refusal. So every pattern is tuned to miss
  rather than fire.

  PII_PATTERNS, checked in this order:
      pan      [A-Z]{5}[0-9]{4}[A-Z]
      aadhaar  \b[2-9]\d{3}[\s-]?\d{4}[\s-]?\d{4}\b
      email    standard
      phone    \b[6-9]\d{9}\b
      account  \b\d{12}\b
      otp      \b\d{4,6}\b  BUT ONLY with an adjacent context word

  Two decisions worth defending:

  - Aadhaar is checked before account. A 12-digit Aadhaar also satisfies
    \b\d{12}\b, so without this order a user would be told to remove their
    "account number" when they had actually typed their Aadhaar.

  - The bare 4-6 digit OTP pattern would fire on every fee percentage in the
    corpus. "exit load 1%", "expense ratio 1.03%", "stamp duty 0.005%", "minimum
    sip 100" are all numbers, not secrets. The digits only count as an OTP when
    a context word (otp, one-time password, verification code, ...) is present.
    test_otp_requires_context asserts both directions.

  Redaction: redact() returns "redacted:pan" or similar, never the value, so
  guard decisions can be audited without writing the secret to a log. chain.py
  logs the KIND only.


6. ONE DELIBERATE DEVIATION: THE ADVICE KEYWORDS

  The spec lists is_advice keywords as: should i, which is best, advise,
  recommend, buy, sell, hold, switch, suitable for me, my portfolio,
  good time to.

  I did not include buy, sell, hold and best as bare words, because as bare
  words they are false-positive machines:

      "which equity fund holds the largest ..."   -> "hold"
      "the best performing fund"                  -> "best"
      "exit load"                                 -> contains no advice word, but
                                                    a "which is best" style
                                                    match is 1 typo away

  The PRD forbids return and performance claims outright, so "best performing
  fund" is not an answerable question anyway -- but it should be refused by the
  no-match gate, not by a keyword that fires on the noun.

  So every entry is a multi-word phrase or an unmistakably imperative form:
      should i | should we | should (buy|sell|hold|switch|invest|exit|redeem|add)
      (buy|sell|switch|redeem|exit|invest in) (it|this|that|the X)
      which is best | what is the best | best (fund|scheme|option|choice)
      which (fund|scheme) (should|do) | suitable for (me|my) | good for (my|me)
      my portfolio | good time to | recommend | advise | advice on
      worth (investing|buying) | is it safe to | can i (buy|sell|invest)

  Verified both directions. All three PRD out-of-scope questions still refuse;
  all seven positive queries pass; plus "which scheme has the lowest expense
  ratio" and "what is the exit load and lock-in period" pass.

      $ pytest tests/test_guards.py -q
      53 passed

  IF THE TEAM PREFERS THE LITERAL LIST, this is a one-line change to
  _ADVICE_PHRASES -- but "the best performing fund" and any "hold"-containing
  question will then refuse. Flagging it as a decision, not a detail.


7. src/rag/prompts.py                    117 lines  (NEW)

  SYSTEM_PROMPT is verbatim from architecture 5.7. Verified by normalised
  comparison, because architecture.md hard-wraps each rule across two physical
  lines and a naive line-by-line grep cannot match it:

      full SYSTEM_PROMPT verbatim in architecture 5.7: True

  (An earlier check of mine reported 7 of 7 rules "not found". That was the
  check being wrong -- it compared single physical lines against wrapped text --
  not the prompt drifting from the source.)

  Constants: DISCLAIMER, ADVICE_REFUSAL, NO_MATCH, PII_REFUSAL, EDU_LINK.
  They are module constants, not model output, so a refusal is byte-identical
  every time. A refusal that is regenerated each time is a refusal that can
  hallucinate, and one that varies between runs cannot be tested.

  A3 DECIDED: EDU_LINK is SEBI's Investor Charter

      https://www.sebi.gov.in/sebiweb/other/OtherAction.do?doInvestorCharter=yes

  Rationale: it is the neutral regulator-published statement of what a mutual
  fund distributor owes an investor, so a refusal does not point the user back
  at the vendor whose page they asked about. One constant, changeable, and the
  spec required deciding it before Phase 4 rather than during it.

  build_user_prompt renders a numbered CONTEXT block and a SEPARATE CONTEXT
  CITATIONS block. The separation is the point: the model must SELECT from a
  supplied list rather than recall a URL, which is what makes validate() able
  to treat a fabricated link as an error instead of something to accept.

  Budget: measured 767 estimated tokens for a 4-hit question, against a
  ~1500-token ceiling. Per-chunk text is capped at 400 tokens as a backstop, so
  top_k changes cannot silently blow the budget.


8. src/rag/generator.py                   94 lines  (NEW)

  temperature=0, max_tokens=300, one call, ~30 s timeout.

  The retry policy is deliberately empty and that is a design decision, not an
  omission. implementation.md 4.3: "a retry inside a live demo reads as a
  hang". A demo that silently waits 60 s is worse than one that returns NO_MATCH
  and lets the user re-ask. The client is constructed with max_retries=0 so the
  SDK cannot add its own backoff behind our back.

  Generator.__init__ raises GeneratorUnavailable with an actionable message if
  the key is missing or the SDK is not installed. answer() re-raises anything
  from the API, because chain.py -- not the generator -- owns the user-facing
  fallback.


9. src/rag/citations.py                  145 lines  (NEW)

  This module is what makes G1 an invariant rather than a hope. Spec order,
  in this exact sequence:

    1. collect URLs via URL_RE
    2. URL not in the retrieved set -> drop it, log citation_mismatch, use the
       top hit's canonical source_url
    3. not a refusal and no valid URL -> NO_MATCH
    4. cap at 3 sentences on a boundary, set truncated=True if anything dropped
    5. return (text, citation_url, truncated)

  URL_RE is kept exactly as the spec pins it, so the trailing-punctuation case
  is absorbed by validate()'s trim rather than by the regex -- the test asserts
  through validate() for that reason.

  One addition beyond the spec: URLs are stripped together with an adjacent
  "Source:"/"Link:" label. Without it, removing the model's citation left a
  dangling "Source:" fragment, which the sentence splitter then counted as an
  extra sentence -- so a correct 3-sentence answer was reported as truncated
  and lost content it should have kept.

  Set membership, not pattern matching, is what catches a fabricated link. A
  near-miss URL is syntactically perfect and reads as plausible to a human
  reviewer, which is exactly why it survives manual QA. Two tests cover it:
  a wholly different URL, and a truncated form of the CORRECT url
  (test_partial_url_is_not_accepted_as_a_hit_url).


10. src/rag/chain.py                     152 lines  (NEW)

  The spec's order is load-bearing, and the reason is cost:

    1. detect_pii     free, offline     -> PII_REFUSAL
    2. is_advice      free, offline     -> ADVICE_REFUSAL
    3. search         paid, offline     -> NO_MATCH if []
    4. generator.answer                -> on ANY exception: NO_MATCH + log
    5. citations.validate               -> repair URL, cap sentences
    6. return Answer

  Steps 1-3 cost zero API calls, so PII, advice and out-of-corpus questions are
  all free. Asserted directly in test_chain.py: advice makes 0 calls, PII makes
  0 calls, out-of-corpus makes 0 calls.

  Every failure after step 3 becomes a normal Answer. There is no code path in
  answer() that lets an exception reach the caller, and the offline path was
  exercised end to end without a key:

      $ python -m src.cli ask "Should I buy HDFC Small Cap Fund?"
      [refused:advice]
      I'm a facts-only assistant for HDFC Mutual Fund scheme pages, ...

      $ python -m src.cli ask "what is exit load, my PAN is ABCDE1234F"
      [refused:pii]
      Please don't share PAN, Aadhaar, account numbers, OTPs, ...

      $ python -m src.cli ask "What is HDFC Bank's FD interest rate?"
      [refused:no_match]
      I couldn't find that on the HDFC source pages I have. ...

  The raw query is never logged on the PII path -- only the kind, via
  guards.redact().

  Answer.hits is populated even on post-retrieval refusals so the debug panel
  still works. Confirmed: a no-key generation failure still printed its 4
  retrieved chunks with scores.

  last_updated is read from the manifest, never from the model, so it is
  identical across every answer in a session.

  The retriever and generator are memoised in module globals. chain imports
  neither sentence_transformers nor chromadb at module level, so the guard
  tests do not pay to load the embedding model. reset_caches() exists for
  tests.
